# 外部协同测试与验收矩阵

## 自动化基线

```bash
npm run test:collaboration
npm run test:access-control
npm run test:domestic-inventory-api
npm run test:stockup-collaboration
npm run build
npm run build:collaboration
```

真实 PostgreSQL RLS 测试必须提供两个不同角色：

```bash
COLLABORATION_TEST_DATABASE_URL=postgres://tongzhou_portal:... \
COLLABORATION_TEST_INTEGRATION_DATABASE_URL=postgres://tongzhou_integration:... \
npm run test:collaboration
```

若只有一个超级用户连接串，RLS 测试应保持跳过，不能据此签署隔离验收。

## 组织隔离

| 编号 | 场景 | 预期 |
|---|---|---|
| ISO-01 | 组织 A 列表/搜索任务 | 仅返回 A |
| ISO-02 | A 使用 B 的任务 UUID 请求详情 | API 404，数据库 RLS 不返回行 |
| ISO-03 | A 使用 B 的附件 UUID 下载 | 拒绝，不签发地址 |
| ISO-04 | A 修改查询参数为 B 的组织/仓库 | 参数不能扩大会话组织边界 |
| ISO-05 | 删除 API 组织过滤后执行数据库测试 | RLS 仍拒绝 B 数据 |
| ISO-06 | 两家包装厂参与同一询价 | 各自只能看到本组织报价；内部集成可比价 |
| ISO-07 | 空组织上下文连接门户库 | 返回零行或拒绝，绝不代表全量 |

## 身份与会话

| 编号 | 场景 | 预期 |
|---|---|---|
| IAM-01 | 连续错误密码 5 次 | 账号锁定 15 分钟；错误信息不泄露账号存在性 |
| IAM-02 | 组织管理员登录 | 必须完成 TOTP |
| IAM-03 | 普通经理确认报价 | 要求近期 TOTP；未绑定时进入绑定流程 |
| IAM-04 | 停用成员 | 其全部会话立即撤销 |
| IAM-05 | 密码重置成功 | 原会话全部撤销，重置令牌只能使用一次 |
| IAM-06 | 邀请过期/重复使用 | 返回失效，不创建账号 |
| IAM-07 | 跨站写请求缺少 CSRF | 403 |

## 数据与同步

| 编号 | 场景 | 预期 |
|---|---|---|
| SYNC-01 | 相同 `Idempotency-Key` 重复提交 | 只产生一条伙伴命令和一条库存流水 |
| SYNC-02 | 旧版本提交 | 409，不静默覆盖 |
| SYNC-03 | 协同 API 离线 | 核心 outbox 保留并退避重试；门户已有提交显示待同步 |
| SYNC-04 | 核心 API 离线 | 伙伴命令保留，恢复后自动处理 |
| SYNC-05 | 入库/出库数量非法或库存不足 | 国内仓主账拒绝，结果回传为失败 |
| SYNC-06 | 调拨收货重复回传 | 国内仓服务幂等返回，不重复入库 |
| SYNC-07 | 盘盈盘亏 | 必须进入中台审批；未批准不得入账 |
| SYNC-08 | 事件乱序 | 旧投影版本被忽略，较新版本保留 |

## 字段和附件安全

| 编号 | 场景 | 预期 |
|---|---|---|
| DATA-01 | 投影包含成本、客户或竞争方字段 | Zod 严格白名单拒绝 |
| DATA-02 | 检查 API 响应、错误、日志和通知 | 不出现原始 WMS/简道云载荷、密钥或内部备注 |
| FILE-01 | 超 50MB 或不允许类型 | 上传票据拒绝 |
| FILE-02 | 恶意文件扫描命中 | 状态 rejected，不允许下载 |
| FILE-03 | 复制短期下载地址并在过期后访问 | 失败 |
| FILE-04 | 组织 A 请求组织 B 附件 | 鉴权失败，即使对象键已知 |

## 国内仓端到端签署条件

选择一家仓库，连续双轨运行不少于一个完整业务周期。入库、出库、调拨收货、差异审批、拍照附件、通知、审计和库存余额全部可追溯；内部库存与实物/旧流程核对无未解释差异后，才可停用旧账号并启动下一家仓迁移。

## 容量与恢复

- 使用 50 家组织、500 个账号、100 并发作为首期压测数据集。
- 重点测登录、任务列表、详情、附件签名、提交与命令拉取；记录 p50/p95/p99、错误率和数据库连接占用。
- 可用性目标 99.9%；完成 PostgreSQL 与对象存储联合恢复演练，验证 RPO 15 分钟、RTO 4 小时。
- OEM 门禁只有在国内仓验收签署、隔离矩阵全通过和恢复演练完成后才允许打开。
