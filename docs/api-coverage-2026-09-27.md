# 中台 API 覆盖审计（2026-09-27）

## 审计结论

中台已经有产品、库存同步、订单、备货协同、生产、仓库协同、妙手、Ozon、资质、货值、用户权限、企业微信、AI 与 Agent Index 等业务 API。当前最明显的缺口不是“没有路由”，而是国内仓进销存只具备页面所需的最小接口，尚不能稳定支持仓库理货和海外仓备货复用。

本次已补齐高优先级缺口：

1. 国内仓仓库轻量列表与库存单据详情；
2. 入库批次、条码、生产日期、有效期和箱规子账；
3. 批次分页查询与追溯字段纠错；
4. 面向海外仓备货的多 SKU 可用量和整箱计算；
5. 查看、入库、出库、调整、档案管理的细粒度权限；
6. Agent Index 中的库存余额、批次和流水只读资源；
7. 独立 OpenAPI 与人工接口文档。

## 接口边界

- 业务写接口继续使用登录会话，不把写权限授予普通 Agent Key。
- 批次和箱规是总库存的子账；总库存仍以“件”为基础单位。
- 不复制产品主数据，批次仅保存当时必要的 SKU、名称和追溯字段。
- 数据范围在服务端执行，不依赖前端隐藏。
- 所有写入保持事务和幂等；出库不会产生负库存。

## 后续建议（未在本次扩大范围）

| 优先级 | 能力 | 原因 |
| --- | --- | --- |
| P1 | 备货单锁定/释放国内库存 | 当前已有可用量读取，但正式自动生成海外仓备货单前需要防止并发超卖 |
| P1 | 仓库扫码理货模式 | 仓库账号开始使用后，应增加移动端连续扫码、重复扫码提示和离线重试 |
| P1 | 批次指定出库（FEFO/FIFO 可选） | 当前默认 FIFO；有保质期产品宜支持按有效期优先出库 |
| P2 | 库位、托盘和箱码 | 仓库规模扩大后再引入，避免第一版增加录入负担 |
| P2 | 盘点任务与差异审批 | 目前调整直接入账，正式多人仓库建议增加盘点单审核 |
| P2 | Webhook/事件订阅 | 可在库存变化后通知备货协同，但需先定义重试、签名和消费幂等协议 |

这些能力不应通过扩展备注字段实现，后续应继续沿用独立业务对象和权限边界。
