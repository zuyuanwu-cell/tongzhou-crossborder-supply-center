# 备货、发货与到仓成本：简道云建表改表清单 V1

版本：V1.0
日期：2026-08-13
适用应用：同舟跨境、千顷ERP
目的：打通运营备货需求、采购/委外生产、发货登记、费用分摊、到仓核销和批次成本确认。

## 1. 配置原则

1. 简道云保存业务主数据，中台是日常操作入口和计算执行方；本地 JSON 只能作为缓存。
2. 现有表不删除、不改字段 ID；新增字段后先小范围试运行，再冻结旧计算字段。
3. 所有跨表关系都同时保存“来源记录 ID”和“业务单号”。记录 ID 用于程序关联，业务单号用于人工查询。
4. `供应链备货审批`位于“千顷ERP”，其余核心表位于“同舟跨境”。跨应用关系一律使用文本字段保存记录 ID，不把关联数据控件作为唯一关联手段。
5. 产品关系以“产品基础信息记录 ID”为主键；正式 SKU 是业务编码，不作为唯一技术主键。
6. 金额、汇率、重量、体积和占比都使用数值控件，不保存为文本。
7. 分摊结果、到仓成本、计算版本、锁定时间等计算字段由中台 API 回写，在简道云页面设为只读。
8. 已锁定的正式成本不得原记录覆盖；调整时作废旧版本并生成新版本。

### 字段责任标识

- `人工`：业务人员在中台录入，中台同步到简道云。
- `系统`：中台自动生成或计算，简道云端只读。
- `带出`：从关联记录带出并保存快照，简道云端只读。
- `选填`：特定场景才填写。

## 10. 新品临时编号与正式编码规则

### 10.1 临时产品号

格式：`TMP-YYYYMMDD-NNNN`，例如 `TMP-20260813-0001`。

1. 运营提交外采新品时，中台立即生成临时产品号。

5. 创建正式发货或 WMS 入库数据之前，产品记录 ID、正式 SKU、产品名称必须齐全。

生成新档案前按以下顺序检查：

## 11. 分摊及成本计算规则

### 11.1 分摊基数

| 分摊方式 | SKU分摊基数 |
|---|---|
| 按重量 | SKU 本行总重量 kg |
| 按体积 | SKU 本行总体积 m³ |
| 按数量 | SKU 本行发货数量 |
| 按货值 | SKU 基础成本人民币单价 × 本行发货数量 |
| 手工分摊 | 人工输入权重；所有 SKU 权重之和必须大于 0 |

### 11.2 公式

```text
SKU分摊占比 = SKU分摊基数 ÷ 本费用全部SKU分摊基数合计
理论分摊金额 = 费用折合人民币金额 × SKU分摊占比
最终分摊金额 = 理论分摊金额四舍五入到2位 + 尾差调整
基础成本总额 = 基础成本人民币单价 × 发货数量
计入成本费用合计 = 该SKU所有计入到仓成本的最终分摊金额合计
预估成本核算数量 = 发货数量
正式成本核算数量 = 实收到仓合格数量
实际成本总额 = 基础成本总额 + 计入成本费用合计
批次到仓单价 = 实际成本总额 ÷ 成本核算数量
含风险预估单价 = 批次到仓单价 × (1 + 物流风险加成率)
```

### 11.3 尾差规则

1. 先以高精度计算每个 SKU 理论金额。
2. 每行四舍五入为人民币 2 位。
3. `费用总额 - 已四舍五入分摊合计`作为尾差。
4. 尾差加到理论分摊金额最大的 SKU；如并列，按发货明细行 ID 升序取第一行。
5. 锁定前必须满足每一笔费用的最终分摊合计等于折合人民币金额。

### 11.4 正式成本锁定条件

同时满足以下条件才允许锁定：

- 发货单状态为“全部到仓”或经管理员确认的“部分到仓”。
- 每个 SKU 都有产品记录 ID 和正式 SKU。
- 实收到仓合格数量大于 0。
- 所有实际费用已确认。
- 每笔费用分摊差额为 0。
- 数量差额已核销或有经确认的异常说明。
- 当前发货明细不存在另一个“正式＋已锁定＋有效”版本。

## 12. 状态流转

```text
备货需求：草稿 → 待审批 → 已批准 → 执行中 → 部分完成 → 已完成
                                   └──────────────→ 已取消

备货明细：待下单 → 已下单 → 生产/备货中 → 部分可发货 → 全部可发货
                                              ↓
                                         部分发货 → 全部发货 → 部分到仓 → 已完成

发货单：草稿 → 待发货 → 已发出 → 运输中 → 部分到仓 → 全部到仓 → 已关闭

成本：待计算 → 已计算 → 待确认 → 已锁定
          └────→ 计算异常
已锁定版本调整：旧版本已作废 → 生成新调整/正式版本 → 待确认 → 已锁定
```

状态只能由中台动作或明确的简道云流程节点推进，不允许普通用户随意下拉跳级。

## 17. 首批验收数据

至少准备以下 5 个测试场景：

## 18. ADR-001：简道云作为业务主数据源

### 状态

已接受。

### 背景

当前中台的备货计划保存在本地 JSON，简道云已有需求、备货、明细和发货历史数据。成本计算涉及多表关系、正式版本锁定和审计追溯，继续双重维护会产生数据冲突。

### 决策

简道云保存业务单据和成本结果，中台负责操作体验、校验、计算和流程编排；中台缓存不作为业务事实来源。跨应用关系使用记录 ID 文本字段，所有成本结果保留版本。

### 影响

- 优点：业务数据集中、可审计，简道云和中台不会各有一套结果。
- 代价：简道云字段调整必须同步更新中台字段映射；写入接口需要幂等、版本校验和失败重试。
- 替代方案：继续使用本地 JSON 被否决，因为无法满足多人协作、持久性和成本审计要求。
