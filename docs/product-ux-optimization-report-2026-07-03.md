# 同舟供应链中心产品体验与优化报告

测试时间：2026-07-03 20:00-20:35（Asia/Shanghai）
测试视角：产品经理 + 真实用户任务流
测试范围：前端渲染、游客产品库、内部登录链路、核心 API 数据、移动端首屏、构建质量

## 一、结论概览

当前项目已经具备供应链中台的核心骨架：产品库、动销、备货、仓库授权、库存快照、资质/素材、仓库信息、快捷导航、企业微信通知、同舟 AI 等模块都已成型，且本地缓存中已有真实同步数据。

但从真实使用场景看，目前还没有达到“稳定交付给运营/采购每日使用”的状态。最主要的问题不是页面数量不够，而是关键路径存在阻断：内部登录返回成功但后续会话失效、README 默认端口会打开到其他应用、根路径访问 404、移动端存在遮挡与横向拥挤、经营指标口径不够自解释。

建议先按 P0/P1 修复登录与入口可达性，再收敛信息架构和业务闭环，否则后续继续加功能会让用户更难判断系统是否可信。

## 二、测试证据

### 1. 构建与启动

- `npm run build` 通过，Vite 生产构建成功。
- `http://localhost:8787/api/health` 正常返回，简道云凭据可用。
- README 写明前端默认 `5173`，但本机 `5173` 已被另一个应用占用，访问后进入“迷雾路书 SOP Workspace”，不是本项目。
- 本项目临时启动在 `5174` 后，`/index.html` 可打开，但根路径 `/` 返回 404。

### 2. 数据现状

使用内部访问码作为 legacy bearer token 测得：

- 产品：基础产品 525，目录产品 228。
- 库存：总库存 109,129；已同步库存 SKU 184；仓库有库存但产品库缺失 126；产品库缺仓库库存 44。
- 动销：分析 SKU 317；缺货 11；补货预警 7；慢销 72；滞销 151；无销售数据 72；仓库未建档 89。
- 备货：建议备货 SKU 20；净建议备货 1,892；委外在产 50,000；WMS 备货单 1,169；待入库 165,553。
- 资质：134 条，全部有附件，过期 1 条。
- 素材：158 条，全部有文件。
- 仓库授权：6 个仓库，2 类 WMS Provider。
- 用户：3 个用户，直营 2，分销 1。

### 3. 关键阻断

通过 `/api/login` 使用 `admin123` 登录时，接口返回 `direct` 用户和 token；但再带该 token 请求 `/api/me`，返回的是 `guest`。原因是后端会把 token 内的 `system` 用户拿去本地用户表查询，查不到后降级为游客。

结果：前端看似登录成功，实际内部页面如动销、备货、仓库授权、库存快照、用户管理、企业微信通知会继续 401。这是当前最大上线风险。

## 三、真实场景问题清单

### P0：必须优先修复

1. 内部登录会话不可用

真实场景：管理员点击“登录”，输入内部访问码后期望进入经营总览和仓库授权。当前接口返回成功，但后续鉴权失败，用户会被锁在游客态或内部接口 401。

建议：
- 修复 `createSessionToken(system)` 与 `getAuth()` 的兼容逻辑。
- 或者废弃 `system` token，访问码登录时直接创建/映射一个可查到的本地管理员用户。
- 加端到端用例：登录后访问 `/api/me` 必须返回 `direct`，并能访问 `/api/movement`、`/api/stockup`、`/api/warehouses`。

2. 默认端口和入口不可控

真实场景：运营或开发按 README 打开 `http://localhost:5173`，可能进入其他应用；打开 `http://localhost:5174/` 又是 404。

建议：
- 启动脚本检测端口占用，自动提示或换端口。
- Vite 根路径 `/` 必须能返回应用首页，不要求用户记住 `/index.html`。
- README 补充“端口占用时如何处理”和实际访问地址。

3. 敏感默认访问码风险

当前 `.env.example` 与 README 均展示 `INTERNAL_ACCESS_CODE=admin123`。真实部署中如果未改，内部数据、用户管理、仓库授权会暴露。

建议：
- 服务端启动时检测默认访问码，生产环境直接拒绝启动或强提醒。
- 登录页文案不要提示具体默认密码。
- 增加首次初始化管理员流程。

### P1：影响日常使用效率

4. 经营总览对内部角色价值高，但游客默认被导向产品中心

游客路径合理，但内部用户登录失败时完全看不到总览，会误以为系统只有产品库。当前信息架构对“我是谁、能做什么、下一步做什么”的反馈不足。

建议：
- 登录成功后自动跳转到经营总览。
- 游客态顶部明确显示“当前为外部产品浏览模式”。
- 内部页被拦截时展示登录弹窗和原因，而不是只依赖 401 后的全局错误。

5. 指标口径不清，容易引发业务误判

例如：产品目录 228，但动销 SKU 317，风险 SKU 241，仓库未建档 89。真实用户会问：“为什么风险 SKU 比可见产品还多？”。

建议：
- 总览卡片加入口径说明：产品库 SKU、仓库库存 SKU、动销分析 SKU 是否同一集合。
- 对“仓库有库存但产品库缺失”“产品库缺仓库库存”设独立治理入口。
- 风险指标拆成“产品库风险”和“仓库孤儿 SKU 风险”。

6. 数据新鲜度需要更强提醒

当前同步时间为 2026-06-28，而测试日为 2026-07-03，订单/库存数据已滞后约 5 天。真实运营会把旧数据当作今日经营状态。

建议：
- 超过阈值时在总览顶部显示红色数据过期横幅。
- 每个核心模块显示“最后成功同步时间 + 下一次自动同步时间 + 失败原因”。
- 今日订单为 0 时判断是“真实为 0”还是“未同步/同步失败”。

补充落地建议：动销页需要按仓库展示诊断结果，而不是只展示 SKU 列表。推荐每个仓库至少显示：授权状态、库存快照行数、订单同步行数、近 90 天订单数、已匹配订单数、超出 90 天窗口订单数、未匹配 SKU 样例。这样可以区分“仓库真的没动销”和“订单同步失败 / SKU 匹配失败 / 数据过期 / 窗口外订单不计入”。

7. 备货建议尚未形成采购闭环

备货中心已有建议、采纳、放弃，但缺少后续动作：生成采购/委外单、负责人、预计到仓、审批状态、复盘。

建议：
- 采纳后生成“待采购任务”或“委外排产建议”。
- 对每条建议展示计算公式：近 7/30/90 天销量、覆盖天数、在产、在途、建议量。
- 增加“已采纳但未下单”“已下单未入库”“已入库待复盘”状态。

补充落地建议：第一阶段可以先把“已采纳”沉淀为页面内的待创建计划队列，展示净建议量、可售天数、委外在产和采纳时间；后续再接简道云或采购单接口自动创建正式备货计划。

### P2：体验与可用性优化

8. 移动端产品库首屏拥挤

移动截图中，搜索区、国家筛选、品牌筛选、产品数、视图切换连续堆叠；右侧“组合 SKU”浮层会遮挡内容。国家筛选横向空间有限，容易被截断。

建议：
- 移动端将筛选收进抽屉或底部筛选面板。
- 组合 SKU 浮层避开筛选区，或只在选择商品后出现。
- 国家/品牌筛选改为可横滑 chip，并显示“更多”入口。

9. 深色视觉有记忆点，但运营后台信息密度偏营销化

首屏视觉较强，适合作为产品展示，但对运营、采购、仓库授权等高频后台任务，用户更需要高密度表格、稳定筛选、批量操作和异常优先。

建议：
- 内部页采用更“工作台化”的布局：异常列表优先、表格列固定、筛选条件可保存。
- 外部产品库保留较强视觉。
- 区分“对外展示体验”和“内部作业体验”两套信息密度。

10. 删除和危险操作仍主要依赖浏览器 confirm

仓库、用户、机器人、快捷导航等删除使用 `window.confirm`，对复杂后台不够可控，也缺少操作后可追溯。

建议：
- 改为业务化确认弹窗，显示影响范围。
- 增加操作日志：谁在何时删除/停用/导入。
- 对仓库删除、用户删除、配置导入增加二次确认文本。

补充落地建议：仓库、用户、企业微信机器人、定时推送、快捷导航分类和链接都应使用统一确认弹窗，明确“会影响什么”“不会影响什么”，避免浏览器原生确认框信息不足。

11. 企业微信通知未配置，自动化价值还未体现

当前机器人 0，定时推送 0。备货、库存快照、异常同步等场景如果不能主动推送，用户仍要每天手动进系统看。

建议：
- 提供默认通知模板：每日库存快照、备货建议、同步失败、资质过期。
- 在总览显示通知配置健康度。
- 允许用户一键发送“今日经营摘要”测试消息。

12. 产品库对外可用，但价格/库存登录后可见的转化路径不清

游客能看到产品图、国家、分销标签，但价格与库存隐藏。真实分销商看到后不知道如何申请账号或联系谁。

建议：
- 在隐藏价格处放“申请分销账号/联系运营”的明确入口。
- 分销商登录后默认只展示其可见价格、素材、资质，避免暴露内部成本。
- 产品详情页加入下载报价单/复制 SKU/加入选品清单。

## 四、建议迭代路线

### 第一阶段：可登录、可进入、可信任

- 修复登录 token 与 `/api/me`。
- 修复根路径访问 404 和端口占用指引。
- 数据过期红色提醒。
- 默认访问码安全策略。

验收标准：
- 输入内部访问码后，刷新页面仍为直营身份。
- 可访问经营总览、动销、备货、仓库授权。
- 根路径能打开系统首页。
- 过期数据在总览明显提示。

### 第二阶段：把异常变成工作台

- 总览增加“需要处理”的异常队列。
- 动销和备货解释计算口径。
- 仓库孤儿 SKU、产品缺库存建立治理入口。
- 备货采纳后进入任务流。

验收标准：
- 运营每天打开首页即可知道今天要处理哪 5-10 件事。
- 每个风险 SKU 都能追溯为什么触发、应该谁处理、处理到哪一步。

### 第三阶段：外部产品库商业化

- 分销商申请/登录路径。
- 产品详情、报价单、素材/资质下载。
- 组合 SKU 清单导出。
- 移动端筛选和浮层优化。

验收标准：
- 分销商能从浏览产品到拿到报价/素材完成闭环。
- 移动端首屏无遮挡，核心筛选 3 步内完成。

## 六、整体评价

这是一个“功能已经铺开，但关键链路还需要打磨”的项目。它最有价值的方向不是继续增加更多模块，而是把现有数据变成可信、可行动、可追责的供应链工作台。

短期先解决登录、入口、数据新鲜度；中期把动销/备货做成每日任务流；长期再强化外部产品库和分销协作。这样系统才会从“能看数据”进化到“能驱动业务动作”。

## 2026-07-07 已落地更新

- 动销缺失排查：`/api/movement` 已返回 `warehouseDiagnostics`，按仓库展示授权、库存行、订单行、近 90 天订单、已匹配订单、SKU 兜底匹配、窗口外订单和未匹配样例。动销诊断面板已支持复制异常摘要和下载 CSV 诊断清单，便于把“某仓库动销出不来”的原因交给仓库或技术同事对账；当前接口验证结果为 6 个仓库全部“正常”，此前主要风险已可通过诊断区分为同步失败、无库存、无订单、窗口外订单或 SKU 匹配问题。
- 动销诊断行动化：仓库诊断新增 `severity`、`actionTitle`、`actionItems`，把“为什么动销出不来”进一步转成“下一步做什么”；页面卡片、复制摘要和 CSV 诊断清单都会带上处理建议，例如补充仓库授权、等待同步完成、修复订单同步失败、同步库存快照、检查订单窗口或核对 SKU 映射。`npm run smoke:api` 已加入字段校验，防止诊断建议回退。
- 单仓动销重同步：动销诊断卡片新增“查看该仓 SKU”和“重同步订单”动作，运营发现某仓库动销异常后可直接只重跑该仓 90 天订单，不必同步全部仓库；订单同步任务会写入操作日志，便于追踪谁在何时对哪个仓库做过排障同步。
- 单仓排障单：动销诊断卡片新增“复制排障单”，会把仓库、国家、WMS、授权、库存行/SKU、订单行、近 90 天订单、已匹配订单、SKU 兜底、未匹配样例、处理建议和同步消息整理成可直接发给仓库或 WMS 同事的文本。
- 未匹配 SKU 治理清单：动销诊断不再只返回最多 5 条未匹配样例，而是按仓库汇总近 90 天未匹配订单 SKU、国家、订单行数、数量、首次出库和最近出库；诊断卡片可直接复制未匹配 SKU 或下载 CSV 治理清单，运营可把“某仓动销出不来”直接转成产品补档、国家 SKU 或仓库 SKU 映射处理任务。
- 超窗订单清单：动销诊断新增 `outOfWindowSkus`，按仓库汇总未计入近 90 天窗口的订单 SKU、国家、订单行数、数量、首次/最近出库和距今天数；诊断卡片可复制或下载超窗订单清单，用于判断“仓库动销出不来”是统计窗口太短、近期订单未同步，还是历史停销。
- 缺 SKU 订单清单：WMS 订单标准化不再直接丢弃“有数量但没有 SKU”的订单行，动销诊断新增 `missingSkuOrders`，展示订单号、货品 ID、商品名、数量、出库/创建时间和状态；诊断卡片可复制或下载缺 SKU 清单，便于让仓库或 WMS 补齐订单明细 SKU 后重同步，避免这类订单静默导致仓库动销缺失。
- 缺 SKU 根因优先级：动销诊断新增 `missing_sku` 原因，当仓库存在订单行但订单明细缺 SKU 时，会优先显示“订单缺SKU”和“补齐订单明细 SKU”，不再被笼统归类为“近90天无订单”；这能避免运营把字段缺失误判为真实无动销。
- 订单同步任务可追溯：动销诊断卡片新增最近订单同步任务摘要，按仓库展示 job 状态、分片完成数、失败分片数、订单数、当前分片和失败分片样例；复制排障单和下载诊断 CSV 也会带上这些信息，方便区分“仓库无动销”与“订单同步任务/分片失败”。
- 神牛印尼仓少计修复：SEA WMS 出库单同步固定 `stage=has_out_storage`，只统计已出库订单；SEA 仓库改为按 `ORDER_SYNC_CHUNK_DAYS` 分片同步，并将接口 total、读取包裹数、SKU 行、页数和是否达到分页上限写入同步结果与动销诊断，避免待处理/已打包订单占满分页导致印尼仓动销只显示少量订单。
- 备货闭环第一步：备货中心已增加“已采纳待创建计划”队列，采纳建议后不会只从列表消失，运营可以继续看到净建议量、可售天数、委外在产和采纳时间，并可退回提醒。
- 删除与高风险动作：仓库、用户、企业微信机器人、定时推送、快捷导航等关键删除动作已改为业务化确认弹窗。
- 操作日志：新增 `/api/action-log` 和“操作日志”页面，记录用户、仓库授权、企业微信通知、快捷导航、备货建议等关键动作；日志会过滤 webhook、password、secret、token、api/app/access key 等敏感字段。
- 操作日志筛选导出：操作日志页新增关键词、对象类型、操作者角色和动作筛选，并支持复制当前筛选摘要、导出 CSV；运营可快速追溯某个仓库重同步、账号开通、企业微信推送或备货处理是谁在何时执行、明细是什么。
- 企业微信通知：通知中心新增默认模板，可一键填入“每日备货提醒”“库存快照日报”“同步异常检查”，并可应用到备货建议和库存快照场景推送。
- 今日经营摘要推送：企业微信通知中心新增“一键发送今日经营摘要”，后端自动汇总经营总览、备货建议、同步健康度、动销诊断异常和 SKU 治理待办；接口支持 `dryRun` 冒烟检查，真实发送会写入操作日志，帮助运营把每日巡检从“登录查看”推进到“主动推送到群”。
- 默认访问码安全：生产环境 `NODE_ENV=production` 下，如果未配置强 `INTERNAL_ACCESS_CODE`，或仍使用开发默认/占位访问码，服务端会拒绝启动；只有显式 `ALLOW_INSECURE_INTERNAL_ACCESS_CODE=true` 才允许临时放行。
- 首次管理员初始化：取消“无用户时自动创建 admin/admin123”的弱默认种子；新增 `/api/setup` 和 `/api/setup/admin`，前端登录弹层会在没有启用的直营管理员时切换为初始化管理员表单，创建后直接登录，且一旦存在直营管理员初始化入口自动关闭。
- 根路径兜底：后端服务在检测到 `dist/index.html` 后，会为 `/` 和前端路由返回应用首页，`/api/*` 仍保持 JSON API；README 和宝塔部署文档已补充“构建后只启动后端也能打开首页”的说明，降低端口或静态托管配置导致的 404 风险。
- 冒烟验证：新增 `npm run smoke:api`，构建后会临时启动后端并自动检查 `/`、`/api/login`、`/api/me`、`/api/movement`、`/api/stockup`、`/api/warehouses`，覆盖登录态和“动销/备货/仓库”关键链路。
- 指标口径说明：经营总览新增“经营指标口径”面板，区分产品库 SKU、动销分析 SKU、仓库孤儿 SKU 和风险 SKU，避免把不同集合的数量直接相互比较。
- 备货计划雏形：备货中心已支持从“已采纳”建议创建本地备货计划，填写计划数量、采购/委外类型、负责人、预计到仓和备注；计划可推进为已下单、生产/在途、已到仓或取消，并写入操作日志。后续可把该本地计划同步到简道云或正式采购/委外单接口。
- 备货计划执行清单：备货计划跟踪区新增“复制执行摘要”“下载执行 CSV”和单条“复制下单信息”，把未完成计划整理成采购/跟单可直接转发的 SKU、数量、类型、状态、负责人、预计到仓和备注清单；在正式采购/委外单接口接入前，先解决已采纳建议难以交付给执行人的问题。
- 到仓复盘清单：备货中心新增“已到仓待复盘”区，保留已标记到仓的计划，展示计划数量、负责人、预计到仓、标记到仓时间和按期/延期结论，并支持复制复盘摘要、下载复盘 CSV 和单条复盘复制，补齐“已入库待复盘”的闭环。
- 资质过期提醒：企业微信通知中心新增“资质过期提醒”模板和 `qualificationExpiry` 场景；资质同步后会扫描已过期及 30 天内到期的资质，场景启用后按摘要推送到群，避免合规证照靠人工巡检遗漏。
- 外部分销闭环：产品详情页新增“复制 SKU”“复制附件链接”“下载附件清单”和“加入选品清单”，组合 SKU 计算器新增报价 CSV 下载；分销商/运营可以从浏览产品直接形成可复制、可下载的报价、素材与资质交付清单。
- 分销账号申请：游客产品库新增“申请分销账号”表单，支持从产品库横幅或单个锁定价格 SKU 发起申请；后端新增 `/api/distributor-applications` 本地保存申请并写入操作日志，避免外部用户只能看到“联系运营”却没有提交入口。
- 分销申请处理：用户管理页新增“分销账号申请”队列，直营用户可查看申请公司、联系人、联系方式、市场、来源 SKU 和需求说明，并将申请标记为已联系、已通过或已拒绝；也可以一键带入创建分销账号，账号创建成功后自动将对应申请标记为已通过，状态更新会写入操作日志，形成外部线索到内部开通的闭环。
- 内部页权限拦截：当游客或权限不足账号通过链接访问动销、备货、仓库授权等内部页面时，不再静默跳回产品库，而是在工作区顶部说明原访问页面、受限原因和登录/联系管理员路径；登录成功后会优先回到原目标页面。
- 首页异常工作台：经营总览新增“需要处理”队列，聚合数据过期、仓库订单同步失败、动销诊断异常、备货建议待处理、已采纳待建计划和仓库孤儿 SKU；每条异常都带数量、原因摘要和跳转动作，运营打开首页即可知道今天先处理什么。
- 首页待办交付物：经营总览“需要处理”队列新增“复制待办”和“下载 CSV”，可把今日数据过期、同步失败、动销诊断、备货建议、通知配置和 SKU 治理待办整理成可转发的日清单，便于早会、群内跟进和责任分配。
- 同步健康口径：经营总览新增“同步健康度”面板，按产品目录、仓库库存、订单出库分别展示最后成功同步时间、下一次自动同步时间和失败/提醒原因；“今日出库订单”为 0 时会区分订单未同步、仓库同步失败导致不完整，或链路已同步但今日真实暂无出库。
- 通知配置健康度：经营总览新增“通知配置健康度”面板，展示企业微信机器人、定时推送、场景推送和最近错误；当机器人未配置、未启用、未启用推送或存在发送错误时，会进入首页“需要处理”队列并可直接跳转到企业微信通知中心配置。
- SKU 治理入口：仓库授权/库存同步页的“数据缺口核对”升级为“SKU 治理入口”，支持按仓库汇总仓库孤儿 SKU、复制待补档 SKU、下载 CSV 治理清单，并把原占位按钮改为明确的产品档案/国家 SKU/仓库编码处理建议。
- 产品缺仓库库存治理：`/api/warehouses` 新增 `productMissingWarehouseItems` 明细，SKU 治理入口并列展示“仓库有库存但产品库未建档”和“产品库有 SKU 但仓库无库存”两类缺口；后一类可复制待查库存 SKU、下载缺库存 CSV，用于检查仓库库存同步、仓库 SKU 映射或是否应下架/补货。
- 备货公式拆解：备货中心的“建议备货清单”和“已采纳待创建计划”新增“计算口径”悬浮说明，逐条展示 7/30/90 天销量、加权日均、可售天数、目标覆盖、在途、建议备货、委外在产和净建议备货公式，避免运营只看到结论却无法判断建议量来源。
- 动销风险执行清单：SKU 动销明细新增“复制风险清单”和“下载风险 CSV”，按当前筛选导出风险 SKU 的状态、建议负责人、触发原因、下一步动作、库存、在途、3/7/30/90 天销量、可售天数和建议备货；让“每个风险 SKU 为什么触发、谁处理、下一步做什么”可以直接进入日常跟进。
- 移动端产品筛选：产品库移动端新增“筛选”折叠入口，搜索框保留在首屏，国家/品牌/结果数收进可展开面板，并提供清除筛选和查看结果动作；国家筛选仍使用横滑 chip，组合 SKU 浮层保持只在已选商品后出现，减少首屏拥挤和遮挡。
- 动销筛选预设：动销监控页新增本地筛选预设，运营可保存常看的国家、仓库、状态和关键词组合，后续一键应用或删除，支撑每日固定巡检仓库/风险状态的工作台化操作。
