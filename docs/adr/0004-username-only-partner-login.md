# ADR-0004：伙伴登录不再填写组织代码

- 状态：已接受
- 日期：2026-09-28
- 补充：ADR-0002、ADR-0003 中的伙伴登录凭据说明

## 决策

伙伴门户登录只要求账号和密码。用户名保持大小写不敏感的全局唯一约束，服务端根据用户名定位唯一成员关系与组织，再创建绑定该成员关系的会话。

组织代码继续保留在数据库、内部中台和集成接口中，用于组织隔离、投影发布与审计，但不再作为伙伴需要保管或输入的登录凭据。开户复制文案只包含伙伴网址、组织名称、登录账号和登录密码；找回密码也只要求账号。

## 隔离约束

- 数据库为 `organization_memberships.user_id` 增加唯一索引，一个伙伴身份只能归属一个组织。
- 登录查询若异常返回多个成员关系，将拒绝登录，不会静默选择组织。
- 登录后的会话仍绑定明确的 `membership_id` 和 `organization_id`，现有 API 权限检查与 PostgreSQL RLS 保持不变。
- 用户名重复仍在开户时被拒绝，邮箱继续为可选资料。
