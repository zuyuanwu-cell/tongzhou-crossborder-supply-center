# ADR-0006：仓库自主作业采用“门户发起、内部审批、主账入账”

## 状态

已接受

## 背景

仓库伙伴需要在门户查看带图片的本仓库存，并能处理内部中台下发的入库、出库、调拨工单。同时，仓库现场还会临时发起入库、出库和盘点差异。若这些操作直接写入内部库存主账，账号误用、重复提交或越权操作会立即影响真实库存；若只提供一个表单而不形成工单，又无法追踪审批、附件、异常和最终入账结果。

## 决策

- 商品图片作为库存投影白名单字段，只接受长度不超过 2000 的 HTTPS 地址；不投影原始简道云载荷、成本或内部附件地址。
- 内部中台发布的普通仓库工单继续按现有规则处理：仓库接单、填写实际数量和凭证，核心后端重新校验后入账；超过计划数量时自动升级为内部审批。
- 仓库自主发起的入库、出库及盘点差异均由协同 API 在本组织私有空间内创建工单和高风险指令，初始状态为 `pending_approval`。
- 内部管理员在现有中台的“仓库作业审批”队列批准或驳回。批准后，核心桥接再次校验仓库、SKU、库存、幂等键和操作类型，再写入国内库存主账。
- 伙伴门户从协作库读取状态、命令结果和事件时间线；库存真值仍只存在于内部主账。
- 所有新建与提交接口继续同时校验组织角色、仓库资源授权和具体业务能力，并由 PostgreSQL RLS 限制组织范围。

## 后果

### 正面

- 仓库现场可以独立发起作业，同时不会绕过内部审批和库存校验。
- 每次申请都有工单、操作者、数量、审批结果、主账单号及幂等记录，可完整追溯。
- 图片和库存仍按组织及仓库授权投影，不扩大外部门户的数据边界。

### 负面

- 仓库自主作业需要等待内部审批，不能即时改变库存。
- 内部管理员需要及时处理审批队列；桥接服务不可用时，批准后的作业会保持待同步。

### 中性

- 首期入库可从本仓已有商品选择，也允许手工录入 SKU；核心主账仍以内部商品目录重新补齐商品信息。
- 首期不支持离线直接入账，移动端只能在联网状态提交。

## 备选方案

- **门户直接调用内部库存 API**：否决。会打破外部协同 API 边界，并扩大内部主账攻击面。
- **仓库自主作业直接自动入账**：否决。无法满足盘盈盘亏和临时出入库的风险控制要求。
- **所有工单都强制人工审批**：否决。内部中台已经批准并下发的正常任务不应重复审批，但超量回传仍需升级审批。
