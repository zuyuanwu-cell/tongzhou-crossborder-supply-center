# ADR-0001：内部中台与外部协同安全边界

- 状态：已接受
- 日期：2026-09-28
- 决策人：同舟供应链产品与研发

## 背景

现有供应链中台原本服务内部运营、分销和仓库人员，后续需接入国内仓、备案服务商、打样工厂、包装厂与委外生产工厂。若仅新增页面或复用现有 `/api/*`，外部账号将进入包含成本、客户、店铺、合同和多供应商信息的信任域，单次权限遗漏即可造成横向泄露。

## 决策

采用“内部主账 + 外部协同门户”的边界：

- 现有中台继续保存库存、成本、合同和审批结果，并保有最终入账权。
- 外部伙伴只访问独立 PWA 和 `/collaboration/*` API，不得访问原 `/api/*`、SQLite、简道云或 WMS。
- 协作 PostgreSQL 只保存字段白名单投影和伙伴提交；不形成第二库存主账。
- 门户数据库角色为非特权 `NOBYPASSRLS` 角色；内部集成使用独立 `BYPASSRLS` 角色。两套连接串不得相同。
- 每个 OEM 合作组织拥有独立项目副本和私有空间。包装报价只允许本组织和内部集成角色读取。
- 核心侧使用本地持久 outbox/inbox，伙伴命令带幂等键与期望版本；库存操作由现有国内仓服务再次校验后入账。
- 保持同一 Git 仓库，但内部前端、门户、核心 API、协同 API 和数据库迁移独立构建与部署。

## 安全控制

- PostgreSQL RLS 与 API 组织条件同时生效；`organization_id` 不允许以空值代表全量。
- 账号密码使用 Argon2id；会话为服务端不透明令牌，Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`；写操作校验 CSRF。
- 组织管理员登录强制 TOTP；库存调整、成员变更、邀请和报价确认要求近期 TOTP。（此项身份决策已由 ADR-0002 替代。）
- 附件进入私有对象存储，下载时重新鉴权并签发短时地址；生产环境要求恶意文件扫描。
- 审计日志只追加；门户角色没有更新或删除审计记录的数据库权限。
- OEM 功能由 `COLLABORATION_OEM_ENABLED` 控制，国内仓试点通过前保持关闭。

## 影响

收益是外部攻击面、内部主账和供应商之间形成可验证隔离；代价是需要维护投影契约、同步状态和独立 PostgreSQL/S3 运维。当前规模采用 PostgreSQL outbox/inbox 和后台轮询，不引入 Kafka 或 Kubernetes。

## 被否决方案

- 只拆前端页面：无法消除共享 API、共享凭证和共享数据库权限造成的越权风险。
- 把现有中台降为纯前端：会丢失主账和审批边界，并形成双主账。
- 立即拆成大量微服务：首期组织与并发规模不足以抵消运维复杂度。
