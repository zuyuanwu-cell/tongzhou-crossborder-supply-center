# 同舟悬浮 AI Agent 设计

## 目标

在中台右侧提供始终可用的“同舟领航员”，基于当前登录用户的权限与数据范围完成页面数据诊断、业务数据理解、问题回答和操作辅助。助手复用用户在“同舟 AI”中保存的个人模型与密钥，不新增共享密钥，也不把业务数据复制到新的数据库。

## 首版边界

- 页面打开只读取已有缓存与索引，不触发 WMS、简道云或妙手的全量同步。
- 即时诊断由服务端规则完成；深度问答才调用用户选择的文本模型。
- 模型只能读取当前账号本来可见的数据；仓库、国家、SKU 和“仅看本人”等范围继续生效。
- 助手可以给出操作步骤和页面跳转，但不会直接修改库存、订单、成本、售后或权限。后续如开放写操作，必须使用独立权限、操作预览和二次确认。
- 对话仅保存在浏览器当前会话中；服务端只记录调用页面、耗时和模型，不记录完整提问正文。

## 接口

- `GET /api/ai/agent/context?route=...`：返回当前页面、数据源更新时间、指标、异常洞察、快捷问题和安全跳转。
- `POST /api/ai/agent/chat`：接收当前页面及最近对话，将权限过滤后的上下文交给用户的同舟画布文本模型，返回回答和安全跳转。
- Agent Index API 增补仓库货值、资质预警、售后单、仓库工单和妙手任务等近期模块，并在 OpenAPI 中声明悬浮助手接口。

## 交互

右下角使用深海蓝与信号橙的圆形入口。展开后为控制塔式侧边面板：顶部显示当前页面和数据状态，中部显示诊断卡与对话，底部提供快捷问题和输入框。模型尚未配置时，规则诊断仍可使用，并明确引导用户前往“同舟 AI”配置个人密钥。

## 验收

- 未登录或没有 `tongzhou_ai` 权限时不显示入口，接口返回无权限。
- 数据范围受限账号不会在上下文、回答或 API 索引中看到越权记录。
- 未配置模型时上下文接口正常，对话接口给出可理解的配置提示。
- Node.js 16 下通过 Agent API、权限、悬浮助手单元测试与生产构建。
