# 系统备份与迁移设计

## 目标与边界

为供应链中心增加管理员专用的“系统备份”板块，支持把主系统的业务缓存、数据库文件和必要配置导出为单一加密备份包，并在同版本系统上完成校验、预览、停机切换和失败回滚。默认场景是跨服务器迁移；同机灾备恢复需要管理员显式选择。

首版只覆盖当前主应用的 `.cache` 数据与根目录 `.env`。外部数据库、对象存储内容和独立协同系统不隐式打包；导出预览会明确提示这些边界，避免形成“全系统已备份”的错误预期。

## 安全模型

- 备份包整体加密，缓存数据库、附件、清单和配置均不以明文落盘。
- 使用 `scrypt` 派生 256 位密钥，以 AES-256-GCM 流式加密；包头只保留解密所需的盐、IV、KDF 参数与格式版本。
- 导出、导入和恢复只允许具备 `system_backup` 权限的管理员，并要求再次输入当前账户密码。旧版内部访问码不能执行这些操作。
- 下载使用短时、一次性票据。工作目录、上传文件、导出文件和审计日志均位于 `.system-backup`，不进入静态目录，也不随业务缓存回滚。
- 解包严格拒绝绝对路径、`..`、符号链接、超额文件数和超额解压体积，防止路径穿越与压缩炸弹。
- API、日志和作业状态不保存备份密码、账户密码或 `.env` 明文。

## 备份包格式

文件扩展名为 `.tzbak`，由固定魔数、JSON 包头、AES-GCM 密文和认证标签组成。密文内容为 gzip 压缩后的顺序归档记录：每条记录包含受限逻辑路径、类型、大小、权限、修改时间和 SHA-256，随后紧跟文件字节。加密内容包含：

- `manifest.json`：格式版本、精确 Git SHA、创建时间、文件摘要与大小、数据边界和环境变量键列表；
- `README.txt`：给人工排障使用的简要说明；
- `.env`：完整配置，仅在密文内存在；
- `cache/**`：主应用缓存与数据库快照。

导入必须与清单中的精确 Git SHA 一致，首版不提供“忽略版本”开关。

## 导出流程

导出采用持久化异步作业。服务器先检查磁盘余量，再开启全局维护锁，阻止新的写请求；停止后台同步和协同桥接并等待进行中的写任务排空。随后在同一文件系统复制 `.cache` 和 `.env` 到稳定快照，复制完成立即恢复正常服务。加密和打包基于该快照异步进行，前端轮询进度，完成后领取一次性下载票据。

维护锁只覆盖快照窗口，不覆盖耗时的压缩和下载。所有阶段均写入独立审计日志。

## 导入与恢复流程

导入分为上传、验证、应用三段：

1. 前端创建导入作业后，以二进制流上传大文件，不经过现有 JSON 请求体缓冲。
2. 服务端在隔离目录中流式解密、解压，验证 GCM 标签、路径、体积、每个文件摘要、清单和 Git SHA，并返回不含机密的预览。
3. 管理员二次确认后，由独立的 PM2 恢复代理执行切换。代理停止主 API，把当前缓存和配置改名为可回滚副本，再把已验证目录原子换入，启动 API 并检查健康状态；任一步失败或代理中途重启，均依据事务日志回滚原数据。

导入默认使用“迁移模式”：沿用目标服务器的端口、路径、数据库地址、对象存储地址和运行开关，只导入业务/API 密钥等可迁移配置。“完整恢复”仅用于同机灾备，显式覆盖全部 `.env`。

## 页面与权限

页面位于“工具与设置 → 系统备份”，沿用现有白色工作区、深蓝标题、橙色主操作、浅蓝表头和卡片边框。页面展示服务健康、备份范围、导出/导入进度、包校验结果、环境变量策略、恢复结果和审计记录。

新增 `system_backup` 权限并限定管理员角色。服务端独立校验角色、权限、会话和重新认证，不依赖前端隐藏菜单。

## 运维约束

- 生产环境只有设置 `ALLOW_SYSTEM_IMPORT=1` 才允许最终应用导入包。
- 主 API 与恢复代理分别由 PM2 管理，恢复代理不随主 API 停止。
- 保留最近一次成功恢复的回滚副本，后续再按容量策略清理；首版不自动删除可能用于人工救援的数据。
- 发布本功能不会自动执行导入、恢复或覆盖线上数据。
