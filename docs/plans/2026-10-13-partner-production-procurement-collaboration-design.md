# 协同伙伴生产与采购工作台设计

## 目标

在现有组织隔离的伙伴门户中，完善委外加工工厂和物料供应商两类使用场景。伙伴只能看到发布给本组织的加工单、采购单、附件与反馈记录；中台继续持有完整订单、成本和审批主账。

## 业务角色与入口

- `production_factory`：导航显示“生产协同”，只处理本组织的生产工单、打样任务以及被授权资料。
- `material_supplier`：导航显示“采购协同”，只处理本组织的采购单。
- `packaging_factory`：保留私有询报价，并可按授权处理包材采购单。
- `warehouse`：保留现有任务与库存入口；非仓库组织不再显示“本仓库存”和仓库作业按钮。
- 组织管理员只管理本组织成员，成员岗位继续限制提交类动作；查看权限还必须通过组织资源授权。

## 私有订单投影

内部中台只向目标组织发布白名单投影：订单号、产品或物料、规格、计划数量、单位、交期、交付地点、付款说明、工厂承包方式以及必要附件。禁止发布内部成本、客户/店铺、其他供应商、内部备注和源系统原始载荷。

生产工单支持两种承包方式：

- `labor_only`：中台或指定供应商提供物料，工厂反馈领料、生产、质检和交付。
- `turnkey`：工厂包工包料。投影同时下发成品行和应由工厂负责的物料/包材行，工厂必须反馈到齐与测试状态。

采购单按一家供应商一个私有任务发布。即使同一内部采购计划涉及多家供应商，也会拆成互不可见的组织任务。

## 结构化反馈

新增追加式订单报告，不覆盖历史：

- 生产进度：生产阶段、完成百分比、已完成数量、预计完成日期和说明。
- 物料/包材验证：关联物料行、到齐状态、到齐数量、测试结果、测试日期和异常说明。
- 采购履约：确认交期、备货、发货、到货，包含承运商和物流单号。
- 异常上报：分类、严重程度、标题、描述、影响数量和预计解决时间。
- 发货反馈：发货数量、时间、承运商、物流单号和凭证。

每次提交要求幂等键和任务期望版本，同时写入伙伴命令、事件时间线、集成发件箱和审计日志。进度反馈不会把整张任务锁成“待同步”；伙伴可继续追加后续报告，核心后端按命令顺序重新校验并入主账。

## 数据与权限边界

- 新增 `partner_order_lines` 保存对外可见的成品/物料行，新增 `partner_order_reports` 保存追加式报告。
- 两张表均要求非空 `organization_id`，启用并强制 PostgreSQL RLS。
- `purchase_order` 只映射到 `procurement` 私有资源；`production_order` 只映射到 `production` 私有资源。
- 列表、详情、搜索、附件、通知和报告接口同时校验组织 ID、资源授权与岗位动作权限。
- `material_supplier` 只能获得采购查看、履约更新、异常上报和附件能力；不能获得仓库库存、生产、报价或其他组织能力。
- `production_factory` 只能获得生产查看、进度、物料测试、异常、交付和生产资料能力。

## 伙伴门户交互

- 总览指标随组织类型变化：生产工厂显示在产工单、临期工单、待测试物料、开放异常；供应商显示待确认采购单、备货中、已发货、开放异常。
- 任务卡直接显示订单号、交期、数量、承包方式和当前最新进度。
- 生产工单抽屉分为订单概况、产品/物料清单、进度反馈、包材到齐与测试、异常/发货、附件和时间线。
- 采购单抽屉分为订单概况、采购明细、交期与履约反馈、发货/异常、附件和时间线。
- 测试失败或严重异常使用高可见红色状态，并要求填写异常说明；可同时上传照片、PDF 或检测报告。

## 测试与验收

- 组织 A 无法通过列表、详情 ID、报告行 ID、通知或附件访问组织 B 的订单。
- 工厂账号看不到采购单和仓库库存；物料供应商看不到生产工单、其他供应商采购单和内部成本字段。
- 重复幂等键不会产生重复报告；过期版本返回 `409`。
- 全包工单可完成“接单 → 包材到齐 → 测试通过/失败 → 进度更新 → 异常 → 发货”的完整链路。
- 采购单可完成“接单 → 确认交期 → 备货 → 发货 → 到货”的完整链路。
- PostgreSQL 迁移、RLS、API 权限、前端构建与桌面/移动页面回归均通过后才能发布。

## 范围约束

- 本阶段不让伙伴直接修改订单数量、价格、物料归属或交期主数据；差异通过报告或异常提交，由中台确认后重新发布版本。
- 本阶段不自动把伙伴反馈写入简道云；继续通过现有 outbox/command 通道由内部中台校验处理。
- 不在门户展示完整供应链、客户、店铺、成本或其他合作组织信息。
