# 库存货值与退货优化设计

## 目标

把库存货值和海外仓退货从“两个快照相减”的展示，升级为可追溯、可解释、可校验的经营台账。第一优先级是阻止错误仓库数据和错误库存口径继续进入中台；第二优先级是统一日期、退货、快照和成本口径；最后再补齐台账、性能与页面体验。

## 数据原则

1. YunWMS 连接必须显式配置仓库编码。编码缺失或返回行不属于目标仓时，同步失败且不写入缓存，禁止退化为全账号拉取。
2. 在库数量只等于 `availableQty + lockedQty`。待入库、头程在途、不良和暂存分别展示，均不进入在库或在库货值。
3. 退货草稿、在途、已收货、已上架、不良、报废和已取消分开统计；已取消不进入数量，草稿只进入“已申请未寄出”。
4. 业务日期由仓库业务时区计算。快照必须记录采集时间、目标日终时间和完整性；缺失日不允许用更早快照静默替代。
5. 历史货值按快照日选取当时已生效的成本和汇率。没有历史版本时明确标记追溯成本，未来成本不得回填历史。
6. 所有汇总都带数据完整性和覆盖率。缺少快照、订单、调拨、盘点或成本时，页面必须显式告警。

## 架构

- 同步边界：在 `server/wms-adapters.js` 和 `server/warehouse-return-query.js` 内做仓库编码、返回行和状态校验，错误数据不得进入后续聚合。
- 统一台账：新增 SQLite 数据层，保存标准化订单与 `inventory_daily_ledger`。索引覆盖 `(warehouse_id, sku, ship_date)` 和 `(biz_date, warehouse_id, sku)`。
- 聚合层：库存货值、动销对比和海外仓对账优先查询台账；历史 JSON 保留只读兼容和一次性迁移入口。
- 估值层：日台账落库时写入成本版本、汇率版本、已计价数量和未计价数量，查询只做范围汇总。
- 接口层：返回统一的日期区间、完整性状态、KPI、异常任务及下钻标识；大响应支持压缩和短时权限隔离缓存。
- 前端层：沿用现有中台视觉契约，增加完整性横幅、统一日期预设、库存与退货 KPI、异常任务表和 SKU 台账下钻；页面按路由懒加载。

## 库存日台账

每个业务日、仓库、SKU 一行，字段包括：期初、采购入库、退货上架、调拨入/出、订单出库、其他出库、调整、期末在库、不良、在途、差异、数据标志，以及成本/汇率版本与货值覆盖率。

公式：

`variance = closing - (opening + inbound + return_restock + transfer_in - transfer_out - order_outbound - other_outbound + adjust)`

只有完整日终快照才能作为 `closing`。缺失或偏离日终容差的快照写入 `data_flags`，不能伪装为完整日。

## 页面信息结构

- 顶部：数据完整性、最近同步时间、缺失源与受影响范围。
- 日期：昨天、近 3/7/15/30 天、本周/上周、本月/上月、自定义；默认截止昨天。
- 库存：期初、期末、净变化、入库、出库、退货上架、调整、差异。
- 退货：申请、已收、未收、已申请未寄出、上架、不良、报废、破损率。
- 对账：应出、实出、漏出、超出，展示数据覆盖状态。
- 任务：未收货账龄、订单不一致、缺成本、缺快照；支持按仓库/SKU 下钻到台账和单据。

## 兼容与发布

现有接口字段在过渡期保留，新增字段向后兼容。运行数据、快照和数据库不进入 Git，也不得在部署中重置。前端发布必须在干净提交上构建到 staging，执行生产 UI 契约检查和鉴权冒烟后原子切换；本任务当前只实现并验证，不直接发布生产。
