# 备货与到仓成本链路实施计划

> 日期：2026-08-13
> 状态：已完成开发与 dry-run 验收
> 范围：中台与已建好的简道云表单对接，不清空、不覆盖正式数据

## 目标

把运营备货需求、供应链执行、发货登记、费用确认、按重量/体积分摊、SKU 成本批次和到仓成本串成一个可在现有中台操作与追踪的闭环。

## 实施步骤

### 1. 固化简道云映射

- 更新 `server/field-mapping.js`，登记需求、备货单、备货单明细、发货单、发货费用明细、SKU 成本批次和产品档案的真实表单 ID 与字段 ID。
- 在独立模块中统一处理简道云字段读取、写入、空值和数字格式，避免页面或路由散落硬编码。

### 2. 实现业务与计算服务

- 新建备货成本领域模块，聚合各表数据并输出需求、执行、发货、费用、成本批次和编码队列。
- 支持费用按重量、体积、数量和指定金额分摊；处理四舍五入尾差，确保明细分摊金额合计严格等于费用金额。
- 计算产品基础成本、分摊费用、单件到仓成本，并生成可预览的成本批次。
- 提供费用新增、计算预览、成本批次确认/锁定等受控接口。

### 3. 改造中台页面

- 在现有备货中心增加“链路总览、需求、执行、发货费用、成本批次、新品编码”工作区。
- 发货费用区支持选择发货批次、填写费用币种/汇率/分摊方式并实时预览。
- 成本预览明确显示分摊基数、分摊金额、单件运费和到仓单价；异常数据不允许确认。

### 4. 验证与交付

- 增加计算单元测试，覆盖重量、体积、数量、指定金额、零基数和尾差。
- 使用本地 mock/纯计算接口验证写入载荷，不在自动化测试中创建或修改简道云正式数据。
- 执行 TypeScript 构建、现有测试和浏览器页面验证。
- 对简道云做只读连通性和字段核验；正式写入仅由用户在页面明确提交时发生。

## 验收口径

- 所有新表和关键新增字段均使用真实字段 ID。
- 同一笔费用的 SKU 分摊合计与费用折算人民币金额一致。
- 同一 SKU 在不同发货批次保留独立成本批次，不覆盖历史成本。
- 无 SKU 的新品可在编码队列中识别并持续追踪。
- 页面可读取当前简道云数据，空表时也能正常展示并引导下一步。

## 验收结果（2026-08-13）

- 已接入 16 条需求、41 张备货执行单、304 条执行明细、51 张历史发货单，并将历史装箱行归并为 234 条 SKU 发货明细。
- 新增需求录入、需求转执行、逐 SKU 生产/外采进度、实际发货、费用登记、成本试算、成本版本锁定和新品编码工作台。
- 已兼容历史备货单按业务单号关联明细；280 条历史执行明细可自动补全所属执行单，剩余无匹配业务单号的记录继续保留只读展示。
- 已兼容历史未建临时产品档案的需求：编码时自动新建正式产品档案并回写来源需求。
- 计算测试覆盖重量、体积、数量、货值、尾差、零基数、缺 SKU、进度约束、超量发货和历史需求编码。
- 真实接口只读联通正常；写接口均以 `dryRun=true` 验收，未向简道云写入测试记录。
