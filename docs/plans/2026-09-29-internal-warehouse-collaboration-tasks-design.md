# 中台发布国内仓协同任务设计

## 目标

在现有“仓库协同中心”增加一条面向外部协同门户的正式任务链路：有权限的中台人员选择协同组织、授权仓库、任务类型和商品明细后发布；仓库在伙伴门户接单、处理并回传；中台实时查看状态、数量、凭证和时间线。同时提供固定的“打开伙伴门户”入口。

## 方案选择

采用独立的“协同任务”板块，与已有“仓库工单”并存。旧仓库工单继续承载催单、物流、费用和日常问题沟通；新协同任务用于需要伙伴门户执行和留痕的入库、出库、备货及异常任务。

没有采用以下方案：

- 直接改造旧仓库工单：旧工单使用本地 JSON/企业微信流程，缺少组织租户、版本、幂等和协作库时间线，强行复用会混淆权限边界。
- 中台浏览器直接调用外部门户 API：会暴露内部凭证并绕过核心桥接的 outbox，无法保证重试和审计。
- 管理员免密进入伙伴账号：会破坏操作者身份和审计记录。快捷入口只打开伙伴登录页。

## 架构与数据流

1. 中台后端读取有效的仓库协同组织及其已授权仓库，并从内部产品目录、国内仓库存生成可选商品白名单。
2. 发布时由中台后端重新校验组织状态、仓库授权、商品字段和数量；前端不能自行传入成本、客户、售价或其他组织字段。
3. 任务写入核心桥接 outbox，并通过现有内部令牌发布到协作 PostgreSQL。协作 API 幂等创建项目、私有空间、工作项、商品行、通知和时间线。
4. 仓库在伙伴门户执行接单、进度、异常、入/出库确认或通用完成。协作库记录当前状态和事件；库存动作仍由核心后端重新校验后写入国内库存主账。
5. 中台通过只读内部接口查询所有协同任务及详情。附件由内部令牌读取，再经中台登录权限代理下载，不暴露对象存储路径。

## 权限与安全

- 新增 `collaboration_task_view`（查看协同任务）和 `collaboration_task_publish`（发布协同任务）。发布权限自动包含查看权限。
- 管理员默认拥有两项权限；普通内部人员可在“用户管理”按需授权；仓库、分销商和访客角色不能获得内部发布权限。
- 任务只能投递给状态为 active 的仓库组织，且目标仓库必须具有 `warehouse.task.view` 授权。
- 对外字段只包含仓库引用、任务编号、说明、截止时间及商品公开字段；图片只允许 HTTPS。
- 写入使用 `Idempotency-Key`，断网时保留在 outbox 自动重试。

## 页面设计

在“仓库协同中心”增加“协同任务”标签：

- 页头：任务数量、待接单、处理中、待中台确认、已完成，以及“打开伙伴门户”“发布任务”。
- 左侧/主体：按状态、组织、关键词筛选的任务列表，展示协同组织、仓库、任务编号、截止时间与更新时间。
- 发布抽屉：组织 → 授权仓库 → 任务类型 → 商品/数量 → 要求/截止时间，逐层约束选择。
- 详情抽屉：状态进度条、计划/实际数量、批次字段、附件、伙伴指令结果与完整时间线。

视觉沿用中台深蓝、橙色强调色、紧凑信息密度和现有响应式断点，不引入新的设计系统。

## 非功能要求与失败处理

- 首期继续满足 100 并发、50 家组织、500 个账号；列表默认 50 条并分页限制。
- 协作 API 不可用时，发布结果显示“已进入待同步”，不会丢失任务；恢复后 outbox 自动发送。
- 查询失败不影响旧仓库工单、库存或组织管理模块。
- 保持 99.9% 可用性、RPO 15 分钟、RTO 4 小时目标；发布继续执行 PostgreSQL/SQLite 备份与可回滚镜像流程。
