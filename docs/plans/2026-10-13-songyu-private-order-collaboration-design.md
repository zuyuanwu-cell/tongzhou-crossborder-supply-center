# 松雨私有单据协同设计

## 目标

让“松雨”作为委外加工工厂，只能看到中台明确发布给松雨组织的委外加工单、物料采购单和打样单，并能在伙伴门户按单据类型反馈进度、物料/包材测试、发货、样品结果和异常。

## 权限边界

- 账号只决定用户属于“松雨”组织，不以用户名、工厂名称模糊匹配订单。
- 管理员先给组织开通“委外加工、物料采购、打样”三个业务空间，再将具体单据发布到该组织。
- 每个工作项都保存非空 `organization_id`；门户列表、详情、附件、提交动作同时经过 API 组织校验和 PostgreSQL RLS。
- 知道其他组织的工作项 ID 或单号也不能读取；没有发布给松雨的单据默认不可见。

## 中台交互

在“协同组织与账号”的组织详情中增加“协同单据”区域：

1. 管理员选择委外加工单、物料采购单或打样单。
2. 填写对外公开的单号、产品/SKU、数量、交期和要求；系统不投影成本、客户、店铺、其他供应商和内部备注。
3. 发布前检查组织是否具备对应业务授权；发布后立即显示在本组织的单据列表中。
4. 列表显示状态、交期、最近同步时间和单据类型，供中台查看处理进度。

## 伙伴门户交互

- 委外生产工厂的“生产协同”页面提供“全部 / 委外加工单 / 物料采购单 / 打样单”切换和数量。
- 委外加工单沿用生产进度、物料/包材到齐与测试、发货和异常工作台。
- 物料采购单沿用履约、发货和异常工作台。
- 打样单支持接单、开始处理、提交样品结果/附件和完成；所有反馈写入不可覆盖的协同事件。

## 松雨初始配置

给组织 `mf-j11qkyn6` 开通三个组织级资源：

- `production`：加工单查看与进度反馈、物料测试、发货、异常、资料提交。
- `procurement`：采购单查看、履约反馈和异常上报。
- `sampling`：打样单查看、处理和结果提交。

当前生产数据中没有匹配松雨的真实源单，因此不生成虚假订单；管理员可在新入口发布真实单据，之后松雨只会看到明确发布给自己的内容。
