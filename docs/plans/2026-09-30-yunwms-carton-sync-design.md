# YunWMS 入库单逐箱同步与安全修正设计

## 问题与目标

中台发运单已经保存箱数与每箱件数，但 YunWMS 建单载荷只发送了发运总件数，并为整行指定一个箱号，导致 `14,400` 件被记录为 `1` 箱。正确结果应是 `200` 个箱号，每箱 `72` 件，总件数仍为 `14,400`。

本次改动同时解决两件事：

1. 后续创建俄罗斯仓入库单时，按箱展开 SKU 明细；
2. 对仍处于“新建”状态的错误入库单使用 YunWMS `modifyAsn` 原单修正，不新建第二张单。

## 数据与校验

- 发运明细必须同时具备正整数的总件数、箱数和每箱件数。
- 建单前强制校验 `箱数 × 每箱件数 = 总件数`；不一致时停止建单并提示先修正装箱数据。
- 同一发运单内的箱号全局连续递增，避免不同 SKU 重复使用同一箱号。
- 每个箱号生成一条 YunWMS item，数量为每箱件数。
- 东南亚 WMS 继续使用原有聚合数量协议，不受本次逐箱展开影响。

## 原单修正安全边界

修正工具默认只预检，显式传入 `--apply` 才写入 YunWMS。写入前必须同时满足：

- 入库单号、参考号、目标仓库与中台记录完全一致；
- YunWMS 单据状态为 `C`（新建）；
- 当前数据可被唯一定位；
- 展开后的箱数、每箱数量和总件数通过本地校验。

修正后重新读取 YunWMS，逐一比对 SKU、箱号和数量，并核对 `box_total` 与 `sku_total`。任何一项不一致都返回失败，且不会改动中台主账或创建新单。

## 提交预览与作废

- 卡片上的首次操作只读取服务端预览，不直接建单；预览展示目的仓、预计到仓、总箱数、总件数和逐 SKU 的箱数/每箱件数。
- 预览返回发运数据版本，最终提交必须携带同一版本；预览后若有人编辑发运或装箱资料，服务端拒绝提交并要求重新预览。
- “提交入库单”使用 `verify=0` 保留新建状态；“提交并审核入库单”使用 `verify=1` 直接交给 WMS 审核流。
- 已提交单据通过 YunWMS `cancelAsn` 作废。调用前核对入库单号、参考号和状态，调用后必须回读到 `X`（废弃）才把中台状态改为“已作废”。
- 对已进入不允许直接作废阶段的单据，中台不做本地假撤回，提示在 WMS 按当前状态进行拦截或后续处理。

## 验收

- 单 SKU `14,400` 件、`200` 箱、`72` 件/箱展开为 200 条 item。
- 箱号为 `1..200`，每条数量为 `72`，合计为 `14,400`。
- 装箱乘积不等于总件数时拒绝创建。
- 多 SKU 时箱号保持全单唯一、连续。
- 现有入库单修正后仍保留原入库单号，状态仍可由仓库继续处理。
- 预览后数据版本变化时拒绝提交；作废成功时 WMS 与中台状态一致，作废后允许重新预览并创建新单。
