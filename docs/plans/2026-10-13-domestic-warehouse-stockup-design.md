# 国内仓备货作业与多去向发运设计

## 目标

把运营备货需求、国内仓现场作业、国内/海外两类发运和成本归集串成可追踪闭环。国内仓伙伴只看到被授权仓库的任务和必要商品信息；中台保留需求、库存、成本和复核主账。

## 业务链路

1. 运营建立备货需求，指定计划到达的国内仓并推送仓库工单。
2. 国内仓工作台展示待签收 SKU、预计数量、到货日期和下一步动作。
3. 仓库按批次完成签收、良品/破损/短缺登记、换箱、批号、商品条码、箱数、箱规、长宽高、重量和照片留证。
4. 验收良品形成可分配数量。同一批次可拆分为多个出库计划，路线可为“海外仓”或“国内客户”，累计分配与发出数量不得超过良品数量。
5. 海外路线继续跟踪国内提货、国际货代、国际运输、海外仓签收/上架；国内路线跟踪承运与客户签收。
6. 仓库登记换箱、贴标、装卸、耗材、仓储、货拉拉及其他费用。运营复核后纳入批次成本，并按数量或指定方式分摊到 SKU。

## 架构

- `stockup-collaboration` SQLite 是备货和成本主账，新增国内仓工单、质检行、费用、发运分配和事件表。
- 独立 `collaboration` PostgreSQL 伙伴门户继续承担账号、组织隔离、仓库授权和现场操作；扩展任务投影与 `stockup_process` 指令，不向伙伴暴露供应商成本等敏感字段。
- `collaboration-bridge` 使用备货工单 ID 作为 `coreRefId`。发布时投影待签收清单；伙伴回传后以幂等命令更新主账。
- 中台备货协同中心新增“国内仓作业”页，展示漏斗、超时、路线、费用图表和工单下钻；伙伴门户首页改为作业驾驶舱。

## 状态与约束

工单状态为 `draft → waiting_receipt → inspecting → ready_to_ship → partially_shipped → completed`，并允许 `exception`。完成条件是：所有行均完成验收；良品数量已全部发运或明确留仓；必填包装字段完整；费用已登记或确认无费用。所有数量、费用和路线变更记录审计事件。回传使用版本号与幂等键，防止重复签收或重复计费。

## 验证

自动测试覆盖工单创建、验收数量守恒、拆分国内/海外路线、超量拦截、费用汇总和重复命令；前后端构建必须通过。浏览器实测覆盖伙伴工作台、工单执行和中台仪表盘三段流程，并检查窄屏布局。
