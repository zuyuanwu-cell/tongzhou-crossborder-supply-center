# 管理员复盘中心设计

## 目标

为管理员提供一个共用时间窗、可点击下钻的经营复盘工作台，集中回答三类问题：谁在使用系统、海外仓协同是否高效、售后问题因何发生。

## 页面结构

- 指挥条：7/30/90 天与自定义日期，统一控制全部图表。
- 总览：活跃用户、操作量、协同任务、响应 SLA、闭环率、逾期数。
- 用户行为：日趋势、用户排行、动作排行、星期/小时热力图。
- 海外仓协同：任务状态、仓库表现、响应时效分布；点击仓库或状态进入工单明细。
- 售后归因：一级原因、处理方式、责任归属、驳回与催办次数。
- 明细下钻：展示与当前图表选择联动的操作日志或协同工单。

## 权限与数据口径

- 导航和 API 均严格校验 `admin` 角色，单独授予普通权限不能访问。
- 默认统计最近 30 天，最大查询 366 天，时区固定为 `Asia/Shanghai`。
- 响应 SLA 为 24 小时，闭环 SLA 为 72 小时；页面明确展示口径。
- 仅返回分析必需字段，不返回登录 IP、User-Agent、客户联系方式或操作详情原始载荷。
- 操作日志只追加，保留上限由 300 提升到 5000；不改写现有业务数据。

## 验收

- 非管理员访问接口得到 403，且看不到导航入口。
- 日期、用户、行为、仓库、状态和售后原因均可点击筛选或下钻。
- 无数据时图表保持稳定并显示空态；数据量达到保留上限时提示覆盖范围。
- Node.js 16 下通过聚合测试、TypeScript 构建和线上健康检查。
