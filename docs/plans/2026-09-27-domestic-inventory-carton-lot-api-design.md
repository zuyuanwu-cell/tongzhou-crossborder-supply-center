# 国内仓批次、箱规与 API 补齐设计

## 决策

采用“SKU 总账 + 入库批次子账 + 出库分配记录”模型。库存余额负责快速看数，批次负责条码、生产日期、箱规和追溯，出库分配负责解释某次出库扣了哪些批次。

总库存基础单位统一为件。整箱入库换算公式为：

`入库件数 = 箱数 × 每箱件数 + 零散件数`

箱数、箱规、零散件数必须是整数；箱子长宽高和单箱重量必须大于零。批次号、条码、生产日期和有效期可选，有效期不能早于生产日期。

## 兼容性

- 现有余额表和流水表不改主键、不重算历史数据。
- 新增正向库存流水自动创建批次；负向流水按 FIFO 扣减批次。
- 上线前库存显示为未追溯数量，不虚构生产批次。
- 旧 `domestic_inventory_manage` 继续作为兼容总写权限，新仓库账号使用更细权限。

## 不采用的方案

- 不把箱规和生产日期拼入备注：无法检索、校验和自动生成备货箱单。
- 不直接把库存单位改成“箱”：不同批次箱规可能不同，且散件出入库会导致总账失真。
- 不在本期引入库位、托盘、箱码：仓库尚未开始规模化扫码理货，过早引入会显著增加学习和录入成本。

## 验收原则

- 每笔写入使用数据库事务；任一 SKU 失败时整单回滚。
- 幂等键重复提交不重复增加库存。
- 仓库和 SKU 数据范围同时作用于余额、批次、流水和备货可用量。
- Node.js 16 环境构建和运行通过。
