# 全包委外采购结算协同设计

## 目标

全包委外不是只有加工单。委外工厂同时作为成品供应商，实际结算依据为简道云中的采购单和采购入库单。因此伙伴端应同时呈现三类相互关联但职责不同的单据：委外加工单负责生产执行，采购单负责采购履约，采购入库单负责确认实收数量和形成应付依据。

## 方案选择

采用“真实采购单独立投影 + 采购入库只读汇总”的方案。没有把采购信息塞进加工单，因为这会混淆生产数量、采购数量和结算数量；也不建立新的协同结算账本，因为简道云采购入库已经是主账，重复记账会产生双主账风险。

每张简道云采购单投影为一张 `purchase_order` 工作项，并通过委外加工单号关联对应的 `production_order`。同一采购单允许多张采购入库单，伙伴端累计展示实收数量、入库批次、应付金额与结算状态。最终可结算数量取采购入库累计实收，不取工厂自行反馈的完工数量或发货数量。

## 数据隔离

- 采购单的供应商 ID 必须与组织绑定的工厂 ID 完全一致；名称只用于兼容缺失 ID 的历史记录。
- 采购入库单必须同时匹配采购单号和同一供应商，禁止仅按委外加工单号宽泛归集。
- 委外加工单仍不投影价格；采购单只公开该供应商自己的行单价、订单金额和对应采购入库应付金额。
- 其他供应商的采购单、采购入库、名称、价格和数量不得进入投影、日志或通知。
- 组织仍需显式开通 `procurement` 资源及相应权限，不因绑定工厂而自动扩权。

## 状态与交互

- 加工单：接单、物料测试、生产进度、异常、发货。
- 采购单：订单确认、备货、交期、发货和异常反馈。
- 采购入库：由简道云同步，只读展示入库单号、日期、实收数量、应付金额和结算状态。
- 伙伴端采购单显示关联加工单，并用“订单数量 / 累计入库 / 待入库 / 应付金额”卡片表达结算进度。
- 尚未产生采购入库时明确显示“未形成结算依据”；分批入库时按批次列示并累计。

## 异常处理

- 采购单缺少供应商 ID、采购单号或委外加工单号时不投影并记录同步失败原因。
- 入库数量大于采购数量时展示超收提示，但不静默修正主账。
- 简道云短时不可用时保留上次成功投影并自动重试，不把采购单或入库单误标为删除。
- 已取消采购单继续投影为取消状态，历史入库和审计记录不删除。

## 验收标准

1. 全包工厂可在同一账号下分别看到关联加工单和采购单。
2. 采购单详情能看到关联加工单、采购明细和多批采购入库进度。
3. 累计实收和应付均来自采购入库单，未入库不形成结算依据。
4. 非本工厂采购单和入库单在列表、详情、接口与日志中均不可见。
5. 来料加工及其他供应商采购链路不受影响。
