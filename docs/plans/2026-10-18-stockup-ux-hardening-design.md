# 备货协同生产级 UX 加固设计

## 目标

本轮只处理已上线现货备货闭环的高风险交互，不扩展定制加工状态机。目标是让仓库人员能够在手机上稳定完成验货，避免长表单数据丢失和计划数量被误当成实收数量，同时让中台清楚区分 V2 现货闭环与历史 V1 单据。

## 交互方案

- 伙伴仓库端保持现有工业化工作台视觉，但在 360–430px 下消除页面级横向滚动；表格转换为卡片，验货抽屉铺满视口。
- V2 验货按 SKU 折叠，卡片头持续显示完成状态。五步校验在移动端全部可见，不再隐藏未完成步骤。
- 每个 SKU 增加“已完成现场清点”确认。计划数量可作为录入参考，但未确认前不得提交审核。
- 验货草稿保存在当前浏览器会话，恢复时显示提示；退出有未保存内容的工单前二次确认，提交成功后清理草稿。
- 批次提供箱数/散件自动计算和沿用上一批箱规，错误提示精确到当前 SKU 的数量、追溯、箱规或凭证。
- V2 任务不再使用“发运分流”文案；现场附件仅描述到货、外箱、破损和换箱凭证。

## 中台方案

- 采购、仓库工单、锁库出运的校验信息放入当前弹窗，并将无前置数据的主操作禁用。
- 国内仓和物流页把历史 V1 操作收进明确标识的“历史流程”区域，V2 作为默认主流程。
- 移动端压缩首屏说明区，操作按钮换行且保持可达；搜索和新增入口不再被压缩。
- 图像加载失败统一回退到可识别的商品首字占位，不显示破图。

## 验收

- 390px 下 `documentElement.scrollWidth === innerWidth`。
- 修改验货数据后关闭会提示，刷新或重新打开可恢复草稿。
- 未勾选现场清点确认时提交按钮不可用。
- V2 页面不要求仓库填写发运路线，V1 操作必须经过历史流程入口。
- 所有弹窗校验在弹窗内可见，关闭按钮和筛选控件具备可访问名称。
