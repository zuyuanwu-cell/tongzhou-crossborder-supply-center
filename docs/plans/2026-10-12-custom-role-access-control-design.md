# 自定义角色与用户权限设计

## 目标

把当前写死在代码中的四类角色，升级为可新增、可修改、可分配的角色模板。每个用户只绑定一个主角色，并可配置少量个人额外允许或单独禁止权限。功能权限与数据范围分开展示、分开解释，解决“已经授权但仍看不到数据”时无法判断原因的问题。

## 权限模型

最终权限按以下顺序计算：

1. 系统安全边界：决定某类账号永远不能获得的敏感能力。
2. 主角色权限：角色模板统一授予的权限。
3. 用户额外允许：只补充该用户超出角色的能力。
4. 用户单独禁止：覆盖角色权限和额外允许，显式拒绝优先。

每个自定义角色仍属于一个安全类型：`admin`、`direct`、`warehouse` 或 `distributor`。安全类型不作为用户看到的岗位名称，仅用于保留现有的内部员工、仓库协作方、外部分销商等信任边界。系统管理员角色受保护且不可删除；新增角色只能使用内部员工、仓库协作方或分销合作方类型，避免通过自定义角色绕过管理员边界。

## 数据结构与兼容迁移

角色与用户继续保存在现有 `.cache/users.json` 中，使现有备份、恢复和部署流程自然覆盖新配置。新增 `roles` 数组，每个角色包含稳定 ID、名称、说明、安全类型、默认权限、状态和系统保护标记。用户新增 `roleId`，保留原有 `role` 字段作为兼容安全类型。

系统启动时若文件中没有 `roles`，自动从现有管理员、直营运营、仓库操作员、分销商四套默认权限生成内置角色，并按原 `role` 给每个用户补上 `roleId`。原有 `permissionOverrides` 与 `dataScopes` 原样保留，因此迁移不会扩大或缩小现有账号的权限。角色修改后，服务端每次请求都会按最新角色重新计算权限，无需重新登录。

## 管理界面

用户管理页增加“用户账号”和“角色模板”两个工作区。

- 角色模板：新增、复制、编辑名称/说明/安全类型/默认权限；展示成员数和权限数。
- 用户账号：创建或编辑用户时选择主角色；账号列表展示角色、个人加权/禁用数量和数据范围摘要。
- 用户特殊权限：按权限组展示“跟随角色、额外允许、单独禁止”三种来源，默认不重复配置角色已有权限。
- 数据范围：国家、仓库、SKU 独立成区，明确说明多个条件同时满足才可见；空范围代表全部。
- 生效预览：展示最终可见菜单、权限来源统计及可能导致无数据的限制条件。

## API 与校验

用户管理接口返回角色列表和角色成员数。新增角色创建、修改接口，以及用户角色调整接口。所有接口继续要求 `users` 权限。

- 角色名称不能为空且不能重复。
- 角色权限必须来自权限目录，并经过对应安全类型的服务端过滤。
- 已分配用户的角色不允许删除；系统角色不可删除。
- 停用角色后不能再分配给新用户；已有成员需先迁移后才能删除。
- 仓库类型用户仍必须至少绑定一个有效仓库。
- 用户不能把自己从最后一个有效系统管理员角色中移走。
