# 妙手同步准确性与时效优化（第一阶段）

对应评审：《妙手订单对接与数据时效评审》P0 全部 + P2 第 1、2 项。

## 准确性修复

| 问题 | 修复 |
|---|---|
| `IN_CANCEL`、`REFUND_REQUESTED`、`REFUNDING` 等「申请中」状态被当成已完成 | 售后状态分为 已完成 / 处理中 / 驳回撤销 / 待确认 四类，只有明确的完成状态或只有完成时间时才算终态；含义不明确的状态（如 `CLOSED`）记为待确认 |
| 历史库里已被误判的记录 | 读取时按新规则重新判定，无需重新同步 |
| 退款缺少单号时用序号做标识，跨页跨店互相覆盖 | 改为 订单标识 + 创建时间 + 金额 |
| 超过 200 页整次同步失败 | 时间窗口自动对半拆分，最小 1 小时 |
| 售后接口失败一次，整次同步记为不健康，阻断切换 | 订单同步照常记成功；失败的售后时间段记入「待补齐」，下一轮优先补拉，补齐前作为单独的切换阻断项 |
| 无时区时间依赖服务器时区解析 | 显式按 `MIAOSHOU_API_TIME_OFFSET`（默认 +08:00）解析，并支持秒/毫秒时间戳 |
| 金额口径单一（买家实付） | 新增口径设置：买家实付（默认，保持历史行为）、订单金额、商品金额、结算到账；对账页同时展示每种口径与 WMS 的差异率，管理员据此选择；另行分摊结算到账金额供后续利润使用 |

对账页新增：同步方式与游标、售后缺口清单、售后处理中笔数、金额口径对比、售后状态字典（待确认状态高亮）。

## 时效优化

- **订单游标增量**：定时任务记录上次同步到的时间点，只拉「游标 − 10 分钟」之后修改过的包裹；默认间隔从 15 分钟改为 5 分钟。游标超过回看天数（默认 3 天）时退回按天回看。手动同步行为不变。
- **售后独立节奏**：售后接口默认 30 分钟一次；有待补齐时间段、手动同步、每日 90 天全量校正时不受限制。
- **妙手入库变更检测**：逐行比较写入前后内容，只有真实变化才升级妙手数据版本；增量子集里的未变化行不再触发重算。
- **WMS / 产品快照按内容计算版本**：经营分析的数据版本不再包含同步时间，而是订单、产品内容的哈希（9 万行约 0.3 秒）。WMS 每 10 分钟同步一次但数据没变时，不再全量重算（此前每次约 55 秒），响应缓存也不再被清空。
- **变化后提前重算**：妙手或 WMS 数据确有变化时，后台立即开始重算，用户打开页面时通常已是新结果。

## 新增配置

```
MIAOSHOU_PERFORMANCE_SYNC_INTERVAL_MS=300000
MIAOSHOU_AFTER_SALES_SYNC_INTERVAL_MS=1800000
MIAOSHOU_API_TIME_OFFSET=+08:00
```

均有默认值，不配置也可运行。

## 新增接口

`PATCH /api/performance-analytics/revenue-basis`，`{ "revenueBasis": "payAmount" | "orderAmount" | "productAmount" | "escrowAmount" }`，需要经营分析维护 + 销售金额权限。

## 上线后核对

1. 打开「经营贡献 → 交易对账」，看「售后状态字典」里是否有「待确认」的状态，把状态原文反馈给开发补充规则。
2. 看「金额口径」中哪一种与 WMS 差异最小，必要时切换。
3. 观察一天：同步方式应显示「按修改时间增量」，售后缺口应为 0。
