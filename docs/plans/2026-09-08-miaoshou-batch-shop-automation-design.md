# 妙手 ERP 店铺批量自动申请设计

## 目标

让管理员在“中台菜单 → 妙手 ERP → 选择自动申请店铺”中勾选多个店铺，并一次性批量开启或批量关闭自动申请运单号，减少逐店操作和等待。

## 交互设计

- 每张有效店铺卡片增加复选框；已解绑或不存在的店铺不可选择。
- 列表工具栏展示已选择数量，并提供“选择当前结果”“清空选择”“批量开启”“批量关闭”。
- “选择当前结果”只选择当前搜索结果里的有效店铺，不触及被筛选隐藏的店铺。
- 批量开启和关闭都需要二次确认；开启提示会进入自动申请队列但不会自动发货，关闭提示不会影响已经申请成功的运单和面单。
- 操作只提交真正需要改变状态的店铺，完成后显示已修改数量和无需修改数量。
- 搜索条件变化时保留已选店铺，但工具栏明确显示总选择数；用户可随时清空选择。

## 后端设计

- 新增 `PATCH /api/miaoshou/shops/batch`，接收 `shopIds`、`autoApplyTrackingNo`，可选接收 `autoFetchWaybill`。
- 服务层先统一校验：店铺 ID 必须存在；批量开启时所有目标店铺必须有效且妙手授权已配置。
- 所有校验通过后才修改内存状态，并只写入一次 `miaoshou-shops.json`，避免部分成功。
- 返回完整妙手页面载荷，并附带批量操作摘要 `updatedCount`、`unchangedCount`、`shopIds`。
- 服务端记录一条批量操作日志，保留操作人、目标状态和店铺数量。

## 安全与异常处理

- 最多允许一次处理 500 家店铺，店铺 ID 去重并拒绝空列表。
- 任一店铺不存在或在开启时已经失效，整批操作不落盘，前端显示具体原因。
- 单店开关继续保留，与批量接口共用相同状态更新规则。
- 批量接口继续使用妙手模块管理员权限，不向普通账号开放。

## 验收标准

- 可选择当前搜索结果中的有效店铺并批量开启、关闭。
- 已失效店铺无法勾选，也无法被批量开启。
- 重复选择、空选择、未知店铺和失效店铺均有确定结果。
- 批量操作只落盘一次且不会出现部分修改。
- 单店操作、定时申请、获取面单等原有功能不受影响。
