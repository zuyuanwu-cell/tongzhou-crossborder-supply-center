# 海外仓退货事实新鲜度设计

## 问题

海外库存对账页读取 `.cache/overseas-inventory-reconciliation.json` 中的 WMS 退货事实，但此前只有人工刷新入口。缓存停更时，接口仍把数据源标记为 `ready`，零退货还会把售后覆盖率显示成 100%，容易把“数据过期”误解为“本期没有退货”。月度首次查询同时读取整个对比窗口内的全部库存快照，生产环境可能超过网关等待时间。

## 方案

- 在现有后台同步调度器中注册 `warehouse-return-facts`，默认每 6 小时同步当月及上月的 WMS 退货事实；缓存过期时，服务启动后优先执行。
- 每个仓库独立更新。同步失败时保留该仓上次成功的订单和成功覆盖区间，只记录本次尝试范围与错误，不用失败结果覆盖可恢复数据。
- 根据全部可查询仓库的最老成功同步时间、覆盖交集、完整标记和错误，生成 `ready / partial / missing` 数据源状态。默认超过 26 小时或未覆盖当前与对比周期即视为过期。
- 没有实物退货时，售后覆盖率返回 `null`；前端显示“暂无实物退货”，不再显示 100%。排名空态区分“新鲜数据下确实为零”和“退货数据不完整/过期”。
- 月度接口只读取当前期和对比期所需的四个边界快照，不再扫描整段窗口的全部快照。

## 失败与恢复

任一仓库同步失败，页面显示 `partial`、最后完整同步时间、有效覆盖范围和失败提示。缓存中的上次成功事实继续可查，但明确不得作为“零退货”结论。下一轮定时任务继续重试；人工刷新入口保持可用。

## 验证

- 单元测试覆盖新鲜、过期、覆盖不足和零分母语义。
- 静态测试锁定边界快照查询，防止恢复为整窗扫描。
- 运行 API 冒烟、前端构建、发布校验和认证 UI 冒烟。
- 上线后确认调度任务成功、退货源覆盖到当前周期、接口冷响应时间和页面提示/排名。
