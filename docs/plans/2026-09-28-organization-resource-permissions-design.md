# 协同组织资源权限设计

## 目标

在现有组织隔离之上增加可运营的资源授权，让内部管理员明确决定某个协同组织能看到哪些仓库、接收哪些任务、执行哪些动作，并为备案、打样、包装报价和委外生产预留同一套能力模型。

## 权限计算

`有效权限 = 组织资源范围 ∩ 组织业务能力 ∩ 成员角色`

- 资源范围：仓库编号或组织类型对应的 OEM 私有空间。
- 业务能力：查看库存、处理任务、确认入库、报价等细粒度能力。
- 成员角色：组织管理员、经理、操作员、财务或只读成员。

内部中台保存组织授权；门户只读取授权结果。伙伴管理员只能维护成员和角色，不能调用授权写接口。

## 数据与接口

- 新表 `organization_access_grants`，唯一键为组织、资源类型、资源编号。
- 内部接口 `GET/PUT /collaboration/internal/v1/organizations/:code/access-grants`。
- 中台桥接接口 `GET/PUT /api/collaboration-bridge/organizations/:code/access-grants`。
- PUT 使用整体替换语义：服务端校验组织类型、资源类型和能力目录，在一个事务内替换并记录审计。

## 界面

- 仓库组织展示国内仓和 WMS 仓列表；勾选仓库后配置该仓能力。
- 其他组织展示与类型匹配的业务能力开关。
- 提供“使用推荐权限”快捷操作和明确的默认拒绝提示。
- 保存后立即刷新授权，不要求重启服务或重新登录。

## 验收

- 未授权仓库的投影被拒绝，库存和任务列表不可见，猜测详情 ID 也返回 404。
- 已授权仓库只出现被授予的能力；角色不足仍不能执行动作。
- 撤销仓库后历史数据保留但门户不可见。
- 外部组织管理员无授权管理接口。
- 迁移、RLS、API、构建和浏览器回归全部通过后再发布。
