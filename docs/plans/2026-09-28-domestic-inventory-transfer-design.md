# 国内仓库存调拨与扫码打印设计

## 已确认方案

采用两段式调拨：调出仓执行“发出”后，库存从调出仓扣减并进入“调拨在途”；只有调入仓确认收货后，库存才进入调入仓。调拨单支持调拨在途、已收货、已取消三种状态。未收货前可取消，取消时按原批次恢复调出仓库存；收货后不能直接撤销，只能通过有审计记录的库存调整处理。

调拨创建时按 FIFO 从调出仓批次扣减，并把每一笔批次分配固化到调拨单。调入仓收货时按这些分配重建批次，继承批次号、条码、生产日期、有效期、箱规、箱子尺寸、单箱重量和单位成本。这样同一个 SKU 跨多个批次调拨时仍可完整追溯。

## 权限和数据范围

- 新增 `domestic_inventory_transfer` 权限；仓库账号默认具备，直营运营和管理员可单独配置。
- 发起调拨必须具备调出仓的数据范围；目标仓只提供启用仓库的名称与编码，不暴露地址、联系人或库存。这样仓库人员可以发起跨仓调拨，但不能借调拨查看目标仓业务数据。
- 调入仓确认收货必须具备目标仓数据范围；管理员可处理全部国内仓。
- 二维码不包含商品、客户或库存数据，只包含中台 HTTPS 深链接。
- 扫码后仍需登录，并重新进行权限和仓库范围校验，二维码不能绕过权限。

## 打印与扫码

入库单、出库单、调拨单提供统一 A4 打印模板，可通过浏览器打印或另存为 PDF。模板包含单据号、状态、仓库、经办人、时间、SKU/批次/数量/箱规明细及二维码。

- 入库、出库二维码打开对应库存流水详情。
- 调拨二维码打开对应调拨详情；目标仓账号在“在途”状态下可直接确认收货。
- 打印内容由当前单据快照生成，不依赖全量库存加载。

## 数据一致性

创建、收货和取消均使用 SQLite 单事务。请求支持幂等键，重复点击不会重复扣减或重复入库。收货和取消对状态使用条件更新，避免两个仓库人员同时操作。所有动作写入现有库存流水和操作日志；在途数量不计入任一仓可用库存。

## 第一版边界

第一版不增加审批流、部分收货、调拨差异索赔和热敏标签模板；先交付整单收货、整单取消与 A4 PDF 打印。后续可基于同一调拨单扩展部分收货和异常签收。
